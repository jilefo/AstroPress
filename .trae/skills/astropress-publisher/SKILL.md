# AstroPress 爆文创作与自动发布

把"主题"变成"已发布的爆文"的完整流水线。创作标准移植自 WorkBuddy 内容创作技能库（爆款标题语料、去AI味禁令清单、选题四基因模型）。

## 前置条件

1. 目标站点的 Webhook API Key（后台 `/admin-ext/webhooks` 创建，权限勾选 `publish`）
2. 站点地址：
   - 本地：`http://localhost:4321`
   - Cloudflare：`https://<your-worker>.workers.dev`（或绑定的自定义域名）

建议把这两项写入环境变量或项目配置：

```
AP_BASE_URL=https://your-site.workers.dev
AP_API_KEY=xxxxxxxxxxxxxxxx
```

## 发布 API（webhook-publisher 插件）

```
POST {AP_BASE_URL}/ap-webhook/publish
Headers:
  Content-Type: application/json
  X-API-Key: {AP_API_KEY}
Body:
{
  "title": "文章标题",
  "content": "Markdown 正文",
  "slug": "url-friendly-slug",        // 可选，缺省由 title 自动生成
  "type": "post",                      // post | page
  "status": "draft",                   // draft | publish（建议先 draft 人工过一眼）
  "excerpt": "摘要，SEO/列表页展示",
  "meta": {                            // 可选，写入 wp_postmeta
    "seo_title": "...",
    "seo_description": "...",
    "focus_keyword": "...",
    "tags": "标签1,标签2"
  }
}
```

- 幂等：同 `slug` + `type` 重复发布会**更新**而非新建（改稿重发安全）
- 限制：body ≤ 5MB，title ≤ 500 字符
- 成功响应：`{ ok: true, id, slug, action: "created"|"updated" }`

查询发布状态：`GET {AP_BASE_URL}/ap-webhook/status?slug=xxx`（同 API Key）
删除：`POST {AP_BASE_URL}/ap-webhook/delete`，body `{"slug": "...", "type": "post"}`

## 标准工作流

### 0. 选题评估门禁（四基因模型）

动笔前先过门禁。一个选题要爆，至少命中「四基因」中的 2 条：

1. **情绪钩子** — 愤怒/共鸣/焦虑/惊讶/治愈/爽感
2. **信息差** — 「我知道你不知道」「行业内幕」「反常识」
3. **身份标签** — 让读者觉得「这就是我」「替我说出口」
4. **行动触发** — 实用工具/清单/立刻能用/可复制

8 维打分（每项 1-5 分，总分 ≥ 30 才值得写）：情绪 × 传播 × 独家 × 身份 × 时效 × 传播锚点 × 可视化 × 门槛。低于 30 分主动向用户建议换角度。

### 1. 明确创作需求

向用户确认（缺省用括号内默认值）：
- 主题/关键词
- 风格（公众号爆款 / 深度长文 / SEO 优化 / 教程指南 / 测评对比 / 小红书种草 / 抖音口播 / 头条深度）
- 字数（3000-5000）
- 发布状态（draft 草稿，推荐）
- 目标平台侧重（公众号 / 小红书 / 抖音文案 / 头条 / 博客 SEO）

### 2. 创作正文（严格 Markdown + 去AI味硬约束）

结构硬性要求：
- 一级标题 1 个 + 小节标题 ≥ 5 个（`##`）
- 配图建议用 `[配图：描述]` 标注，或直接给可用的无版权图链接（unsplash）
- **代码块必须标注语言**（```python ```bash 等）
- 段落短、有金句
- 结尾有总结 + 行动引导

**去 AI 味硬约束（写作时必须遵守，不是事后润色）：**

- 【禁用词】此外/然而/因此/总而言之/事实上/值得注意/换句话说/首先其次最后/拆一拆/盘一盘/划重点/敲黑板/拆解/梳理/剖析/解构/赋能/助力/闭环/抓手/落地/引爆/重塑/至关重要/不可或缺/深远影响/标志着/彰显了/行业报告显示/专家认为/研究表明/未来可期/前景广阔/综上所述
- 【句式禁令】禁「不是A而是B」「不在于A而在于B」「看似…实则…」二分壳；禁三项式排比（改两项或四项）；「一旦…就/只有…才/无论…都/随着…的发展」全文最多 1 次；默认不用「你」（确需推演最多 1 次「试想」）
- 【标点禁令】揭晓式破折号一律禁（「答案很简单——专注」→「答案是专注」）；「核心是：」「原因有两个：」等提示语冒号删提示语直写内容；引号用「」
- 【替换手法】然而→可/但/其实；因此→所以/就；抽象→具象（紧张→手在抖；提升效率→快了多少、省了几个人；优化流程→把流程改顺了）；长短句交错制造呼吸感

### 3. 生成爆款标题（3-5 个候选）

**16 个公式库**（一个主题至少套 4 个，避免角度雷同）：

| 公式 | 结构 | 范例 |
|---|---|---|
| 实体锚定 | 知名实体+做了什么+为什么重要 | 独家：阿里全面禁用 Claude |
| 数字反差 | 花[极小的钱]+做成[极大的事] | 花68元，让 AI 干完一个小团队的活 |
| 数字清单 | N 个/N 步+结果 | 5 个让你加薪翻倍的职场习惯 |
| 悬念钩子 | 别再/原来/这才是+反常识结论 | 原来真正的自律不是靠坚持 |
| 反差对比 | A 和 B 差在+关键点 | 月薪 3k 和 3w 的人，差在这 3 个思维 |
| 痛点戳心 | 踩过的坑/没人告诉你+场景 | 租房踩过的 5 个坑，个个都是血泪 |
| 利益承诺 | 一招/直接抄+具体好处 | 这套模板直接抄，周报 5 分钟搞定 |
| 共鸣共情 | 是不是/有没有+普遍情绪 | 是不是每次开会你都在假装认真 |
| 反常识颠覆 | 其实/越X越Y+颠覆认知 | 越努力越平庸，问题出在哪 |
| 阴谋揭秘 | [大公司]偷偷[做了某事] | 没人告诉你的行业隐形规则 |
| 亲测转变 | 实测X后，我改变了看法 | 实测一个月，我承认之前的偏见错了 |
| 身份场景 | 身份+高频痛点+新解法 | 写给所有正在被 KPI 折磨的人 |
| 收益损失 | 错过X，可能失去Y | 错过这波趋势，可能多走 3 年弯路 |
| 问题悬念 | 现象+为什么？/ X值得吗 | AI 会接管 618 吗？ |
| 隐藏机制 | 现象背后，真正驱动它的是X | 看懂这件事的底层逻辑才算入门 |
| 具体场景 | 从[痛苦动作]到[新动作] | 从熬夜硬扛到 10 分钟搞定 |

**7 个加辣增强器**（可叠加，只改表达不加事实）：时间前置（刚刚/今天凌晨）、热词前置、具体化代替抽象（「效率提升」→「68 元」）、省略号留白（句尾…）、身份反差、信息缺口（只说发生了什么不说是什么）、口语加语气（啊/吗/了+引号）。

**违规词过滤（命中即替换或删除）**：
- 绝对化：最/第一/唯一/顶级/绝无仅有/100%/保证/必中
- 夸大承诺：月入10万/一键暴富/白捡/稳赚不赔/躺赚
- 诱导逼迫：不看后悔/不转不是/最后一天/手慢无
- 医疗金融法律高危：治愈/根治/包治/特效/无副作用/保本/无风险/内幕/翻倍/必赢/包过
- 标题党高频：震惊/惊呆/吓尿/吐血整理/紧急扩散

**标题党红线**：标题承诺的（揭秘/教程/具体数字）正文必须兑现，不兑现就改标题。

字数规范：公众号 ≤ 30 字、小红书 ≤ 20 字、抖音 ≤ 30 字、博客 SEO ≤ 60 字符。
让用户选 1 个（或直接用最稳妥的第 1 个）。

### 4. 平台风格速查

| 平台 | 风格要点 |
|---|---|
| 公众号 | 开头 3 秒抓人（提问/冲突/反常识），每段 ≤4 行，金句频出适合截图，结尾引导点赞在看转发 |
| 小红书 | 标题带 emoji，正文口语化多换行每段 1-2 句，「姐妹们/谁懂啊」社区语气，结尾 3-5 个话题标签 |
| 抖音口播 | 前 3 秒必须钩子，全文适合朗读，结构=钩子→痛点放大→解决方案→行动指令，标注停顿/重读 |
| 头条 | 开头交代新闻由头或数据，小标题切割每节一个观点，案例数据增强可信度，结尾留讨论话题 |
| 博客 SEO | 标题含核心关键词，关键词密度 2-3%，H1>H2>H3 层级，含 FAQ 小节，内链建议 |

### 5. 组装 meta

- `excerpt`：120 字内，含核心关键词
- `seo_title`：≤ 60 字符
- `seo_description`：≤ 160 字符
- `focus_keyword`：1 个核心词
- `tags`：3-6 个，逗号分隔

### 6. 发布前质量门禁（逐项自检）

- [ ] 标题过违规词表 + 标题党红线（承诺必兑现）
- [ ] 正文无禁用词/禁句式/禁标点（去AI味清单逐条过）
- [ ] 代码块标注语言、图片用绝对 URL
- [ ] meta 五项齐全（excerpt/seo_title/seo_description/focus_keyword/tags）

### 7. 发布

```python
import requests, os

resp = requests.post(
    f"{os.environ['AP_BASE_URL']}/ap-webhook/publish",
    headers={"X-API-Key": os.environ["AP_API_KEY"]},
    json={
        "title": title,
        "content": markdown_body,
        "status": "draft",          # 先用 draft
        "excerpt": excerpt,
        "meta": {"seo_title": seo_title, "seo_description": seo_desc,
                 "focus_keyword": keyword, "tags": tags},
    },
    timeout=60,
)
print(resp.status_code, resp.json())
```

- 201/200 + `ok:true` → 成功，返回后台预览链接 `{AP_BASE_URL}/admin/posts/{id}`
- 401 → API Key 错误；403 → Key 无 publish 权限；413 → 正文超 5MB

### 8. 发布结果汇报

向用户报告：
- 文章 ID、slug、草稿/发布状态
- 后台编辑链接：`{AP_BASE_URL}/admin/posts/{id}`
- 前台预览链接（publish 状态时）：`{AP_BASE_URL}/{slug}`
- 提醒：草稿需在后台点「发布」或改 status=publish 重新调用一次本 API（同 slug 幂等更新）

## 注意事项

- **永远先 draft**：AI 生成内容需人工过目后再 publish，除非用户明确要求直接发布
- 正文不要含 HTML 大段标签（编辑器按 Markdown 渲染）
- 图片用绝对 URL；本地图片需先通过媒体库上传（`/api/media/upload` 需登录态，不在本 SKILL 范围）
- 批量发布多篇时串行执行，间隔 ≥ 2 秒（尊重站点限流）
